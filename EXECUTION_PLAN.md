### График: сводка нагрузки и интервалов

Локально реализована [#33](https://github.com/albazrov/reminder_bot/issues/33):
«📅 График» → «📊 Сводка» открывает полный месячный график и нагрузку
после утверждения, до него — явно помеченный черновик. Утверждённая версия
показывается с актуальными заменами, без подмены неутверждёнными правками.
Доступны текущий/следующий месяц, листание, обновление и возврат в «График».
Загрузка вынесена из event loop; запоздавший результат не заменяет новый экран.

Нагрузка считается по уникальным фактическим дням. Первый интервал —
от последнего известного служения, остальные — между назначениями
по порядку; недели перечисляются через запятую. История берётся из
утверждённых графиков с заменами, при их отсутствии — из сохранённой
истории подготовки плана. Неизвестный первый интервал — «нет данных»,
неполные недели округляются до одного десятичного знака. Тот же блок
интервалов используется перед утверждением. Руководства и эскизы обновлены;
в issue есть ручной чек-лист после test deploy.

Проверки: профильный набор — 253 теста OK; полный — 882 теста OK,
11 skipped на macOS. Проверены замены в истории и текущем месяце,
приоритет утверждённого снимка, уникальные дни, нулевая нагрузка,
неизвестная история, дробные интервалы, месяцы на границе года,
права, ошибки БД, полное листание и запоздавший результат.
`compileall` и `git diff --check` прошли. Commit/push не выполнялись.

### Диагностика оставшихся частей экранов в test

По запросу прочитан debug-лог test без изменения Pi. В 23:05:29
завершение импорта Excel зарегистрировало экран 1913; в 23:05:32
переход в «График» успешно удалил именно его. На скриншоте осталась
первая часть текста импорта. `_send_dialog` по умолчанию делит текст
по 500 символов, но сохраняет ID только последнего сообщения.
Предыдущие части составного экрана поэтому не очищаются.
В 23:17 переходы напоминаний последовательно удаляли свои прежние меню;
ошибки смешения источников данных не обнаружены. Это дефект очистки
составных экранов; исправление в эту диагностическую проверку не входит.

### PR #31: локальные исправления Greptile и возврата из «Авто»

Исправлены все четыре подтверждённых inline findings PR #31:

- Замены вручную и по опросу сравнивают предупреждения до и после замены.
  Уже принятый исполнитель обязанности вне смены не блокирует остальные
  замены. Новый исполнитель вне смены по-прежнему требует утверждения
  графика; отсутствие допуска и другие структурные ошибки не обходятся.
- Связанный отказ проверяет привязку к исходной задаче один раз.
  Отказ по обязанности из утверждённого графика сохраняется в той же
  транзакции даже после удаления допуска/контакта этой обязанности.
  Прямой ответ без привязки запрещён, повторный отказ идемпотентен,
  ошибка записи откатывает оба ответа. Уведомления и поиск замен получают
  оба связанных отказа.
- Восстановлен потоковый ремонт недобора независимых задач при наличии
  обязанности. Основная роль её выбранного исполнителя закреплена;
  обязанность не расходует отдельное место или второй день служения.
  Проверены цепочки перестановок при совпадении фактических дней соседних
  недель, мягкие лимиты и сохранение назначенного исполнителя обязанности.
- Сохранённые недоступные адресаты заметки видны с пометкой
  «недоступно — убрать». Их можно исключить, сохранить адресатов и
  продолжить редактирование; добавить недоступного адресата нельзя.

Дополнительно: «⬅️ К графику» из плана без опроса возвращает на основной
экран «📅 График», включая повторное открытие и возврат из редактора.
Для плана по опросу сохраняется «⬅️ К опросу».

Проверки: профильный набор — 418 тестов OK, 1 skipped;
полный — 873 теста OK, 11 skipped на macOS. Telegram и внешние загрузки
