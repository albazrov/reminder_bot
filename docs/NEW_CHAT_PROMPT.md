Промт рассчитан на доработку проекта и исправление ошибок, но не разрешает
самостоятельно выпускать изменения.

Правила выполнения:
- Если пользователь просит реализовать изменение или исправить баг, исследуй
  весь затронутый путь, найди существующие helpers/patterns, сделай полное
  точечное исправление и добавь регрессионные тесты. Не ограничивайся планом.
- Если пользователь просит только анализ, объяснение или план, не меняй код.
- Не выбирай самостоятельно поведение, если есть существенная неоднозначность

- Сохраняй совместимость и инварианты проекта: доступы, callback-форматы,

  должны быть видимы через принятые логирование/уведомления, без тихих
  fallback'ов.
- После изменения запусти подходящие тесты; для Python-кода — целевые тесты,
  полный набор unittest-тестов, compileall и `git diff --check` согласно skill.
  Не запускай live bot, не отправляй Telegram-сообщения и не используй
  prod/test credentials для проверки.
- Не выводи токены, содержимое `*.env`, персональные данные, полные журналы,
  расписания или личные сообщения. Не копируй код на Pi через ssh/scp.
- На Mac временные файлы храни внутри проекта (тесты и их логи —
  `.tmp/tests/`) либо максимум на один уровень выше корня проекта.
  Не используй системный temp; приватная диагностика — каталог 700, файлы 600.
- Не меняй `test` или `main` напрямую, не делай force push и не переписывай
  чужие изменения.
- Коммит, push, создание/слияние PR, deploy, restore и иные действия с
  рабочими средами выполняй только при явном поручении пользователя в этом чате.
  Разрешение из прошлой задачи не является постоянным разрешением.
- Перед запрошенным commit/push проверь полный diff и независимо проверь
  корректность значимых изменений; новые PR review-комментарии нужно читать
  отдельно от статуса CI/Greptile.
- Обновляй документацию, напрямую связанную с поведением или процессом.
  Не запускай соседние задачи из плана автоматически.
